First release distributed as a container image, and the release that makes environment configuration actually work.

## Container image

pico-auth is an application, not a library, so it ships as an image instead of a PyPI package:

```bash
docker run -p 8100:8100 \
  -v ./application.yaml:/app/application.yaml:ro \
  -e AUTH_ISSUER=https://auth.example.com \
  -e AUTH_ADMIN_PASSWORD=a-strong-random-password \
  ghcr.io/dperezcabrera/pico-auth:0.3.2
```

The image installs from source (it used to `pip install pico-auth`, which now resolves to a frozen release), carries its real version, and exposes a healthcheck against the OIDC discovery endpoint.

## Environment configuration

`main.py` passed an `EnvSource` alongside the YAML, but every settings class binds with `mapping="tree"` and pico-ioc keeps flat and tree sources in separate buckets — the flat source was never consulted, so `AUTH_ADMIN_PASSWORD` and friends silently did nothing. Values now arrive through `${ENV:VAR}` interpolation inside the YAML:

```yaml
auth:
  issuer: "${ENV:AUTH_ISSUER}"
  admin_password: "${ENV:AUTH_ADMIN_PASSWORD}"
```

A referenced variable that is not set now stops startup with `Missing ENV var AUTH_ADMIN_PASSWORD` instead of quietly falling back to the field default — that half of the fix lives in pico-ioc 2.5.1, which this release requires.

## Also in this release

- The bundled `application.yaml` no longer enables `auto_create_admin` with the password `admin`, the exact combination the bootstrap fail-fast rejects. The image could not start as shipped.
- `LocalJWKSProvider` no longer subclasses `JWKSClient`. The container key is a lookup token, so the override needs nothing but `get_key`; the inherited HTTP fetcher and the private attributes mirrored to keep it quiet are gone. Requires pico-client-auth >= 0.7.0, which exports the key from its facade.
- The obsolete `_register_route` monkeypatch is deleted: pico-fastapi has forwarded `@requires_role` / `@allow_anonymous` markers itself since 0.3.1.

## Compatibility

Existing tokens, routes, claims and JWKS are unchanged. Two deployment changes: anything relying on bare `AUTH_*` environment overrides must move those fields to `${ENV:VAR}` in the YAML, and an `application.yaml` that bootstrapped an admin now needs a real password.

## Tests

103 passing, 11 docker end-to-end deselected by default. The image was verified end to end: healthcheck green, issuer resolved from the environment, admin bootstrapped, login returning an RS256 token.
