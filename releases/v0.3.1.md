Maintenance release: PyJWT replaces the unmaintained python-jose, and the dependency floors move up to the versions that actually carry the fixes this server relies on.

## What's changed

`JWTProvider` signs and verifies through **PyJWT** (`PyJWT[crypto] >= 2.8`) instead of python-jose, which has gone unmaintained. Tokens, claims and the JWKS document are byte-for-byte what they were: tokens issued by 0.3.0 keep validating, and the ML-DSA path was never touched by this (it has always been the custom `pqc_jwt` encoder).

Dependency floors now name the versions that fix problems this application hits:

- `pico-client-auth >= 0.6.0` — mandatory `exp`, `HS*` rejection, fail-closed revocation.
- `pico-sqlalchemy >= 0.5.1` — DDL no longer hangs when run under uvicorn.
- `pico-ioc >= 2.3.3` — idempotent container shutdown.

## Distribution

**This release is not published to PyPI.** pico-auth is a deployable application rather than a library, and the repository's own conventions say so; the PyPI entry stays frozen at the versions published before this decision. Install from a checkout:

```bash
pip install -e ".[dev]"      # add ,pqc for ML-DSA support
python -m pico_auth.main
```

## Compatibility

No API changes. Routes, claims, token format, JWKS and configuration keys are identical to 0.3.0. Python >= 3.11.

## Tests

103 passing, 11 docker end-to-end tests deselected by default, against pico-client-auth 0.6.0 and pico-sqlalchemy 0.5.1.
